# Task 002.1 - Cross-Tenant Regression Tests

## Objective

Create an automated regression test suite that validates tenant isolation.

## Implementation Report

### Files Created

- `apps/web/tests/tenant-isolation/cross-tenant-regression.test.ts`
- `tasks/review/002.1-cross-tenant-regression-tests.md`

### Files Modified

- `apps/web/features/auth/services/get-current-app-user.ts`
- `apps/web/package.json`
- `package.json`

### Decisions Made

- Reused the current stack with `node:test` executed through `tsx --test`
- Isolated test data from development data by deriving a dedicated PostgreSQL
  schema named `tenant_regression`
- Exercised real tenant-aware application services and representative mutations
  instead of building a parallel fake authorization layer
- Added a narrow test-only current-user override hook so tenant-aware services
  can run without the full Next request cookie runtime

### What Was Intentionally Left Out

- No browser E2E framework was introduced
- No second database container was required because schema isolation is
  sufficient for regression coverage here
- No broad mocking of app services was added; the suite prefers real Prisma
  reads and writes

### Risks

- The suite currently depends on PostgreSQL being available at the configured
  `DATABASE_URL`
- The current-user override hook is intentionally small, but future changes
  should keep it test-only in usage
- Cross-tenant coverage currently focuses on the critical V1 service and
  mutation paths rather than every single server action in the repository

### Validation

- `pnpm test:tenant`
- `pnpm lint`
- `pnpm --dir apps/web typecheck`
